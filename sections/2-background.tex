\section{Background}
\label{sec:background}


\subsection{Congruence closure}

\emph{Congruence} ($\equiv$) requires that two terms with the same function
and pairwise-congruent children must be congruent, i.e. $f(s_1,
\ldots, s_k) \equiv f(t_1, \ldots, t_k)$ whenever $s_i \equiv t_i$ for every
$i$. \emph{Congruence closure} refers to the problem of building the smallest
equivalence relation that contains a given set of equalities and is closed under
congruence.

Typically, congruence closure is implemented using a datastructure called an
\emph{e-graph}~\cite{egraphs}, which extends a union-find
datastructure~\cite{unionfindtarjan} to represent equivalence classes of terms,
while maintaining congruence.


\begin{definition}[]
    We define $T$ to be a set of \emph{terms} over function symbols $F$, where
    each $t\in T$ is either a \emph{leaf term}, for example $x, y, z$ or a
    \emph{compound term} of the form $f(t_1, \ldots, t_k)$ where $f\in F$
    $\text{arity}(f) = k$ and $t_1, \ldots, t_k \in T$.
\end{definition}

We say that term $x$ is the \emph{child} of $f(x)$ and conversely $f(x)$ is the
\emph{parent} of $x$.

\begin{definition}[Congruence Closure]
    Given $(F, T, E)$ where $F$ is a list of function symbols, $T$ is a set of
    terms over $F$, and $E = \{a_1 = b_1, \ldots, a_n = b_n\}$ is a set of
    equalities between terms in $T$ where $a_1, \ldots, a_n, b_1, \ldots, b_n
    \in T$, the congruence closure ($\equiv$) of $(F, T, E)$ is the smallest
    equivalence closure of $=$ over $T$ that respects congruence. More
    specifically:
    \begin{enumerate}
        \item $a_i \equiv b_i$ for every $i$ (input equalities $=$).
        \item $s \equiv s$ for every term $s$ (reflexivity).
        \item If $s \equiv t$ then $t \equiv s$ (symmetry).
        \item If $s \equiv t$ and $t \equiv u$ then $s \equiv u$ (transitivity).
        \item If $s_i \equiv t_i$ for every $i$ then $f(s_1, \ldots, s_k) \equiv
        f(t_1, \ldots, t_k)$ (congruence).     
    \end{enumerate}
\end{definition}


SMT solvers determine the satisfiability of a first-order logic formula by using
a Boolean Satisfiability (SAT) solver to search for a satisfying assignment to
the propositional skeleton of the formula and then using a theory solver to
check if the assignment is consistent with the theory. Congruence closure is
useful in practice when dealing with the theory of uninterpreted functions (UF).
Given a formula $\phi = a_1 = b_1 \land \ldots \land a_n = b_n \land s \neq t$,
an SMT solver will run congruence closure on the equalities $E = \{a_i =
b_i\}_{i=1}^n$ to obtain the congruence closure $\equiv$ of $E$. Then, it will
check if $s$ and $t$ are in the same equivalence class under $\equiv$. If they
are, then we know that $s \neq t$ cannot be true and thus the formula $\phi$ is
unsatisfiable.


Equality saturation, on the other hand, asks: given a program $P$ and a set of
rewrite rules $R$, what is the ``best'' program equivalent to $P$ under $R$?
This can be treated as a congruence closure problem. We repeatedly
apply the rewrite rules $R$ to $P$, and use congruence closure to maintain the
equivalence class of programs equivalent to $P$. After congruence closure
reaches saturation or times out, a cost function is used to select the best
program $Q$ from $P$'s equivalence class.



\subsection{Motivating Example}
\label{sec:bg:motivating}

To make the structure concrete, consider the formula which is solved by an SMT
solver:
%
\begin{equation}\label{ex:formula}
\begin{aligned}
& \;\;\;\;\;\; a_0 = b_0 \land\; a_1 = b_1 \land\;g(f(a_0), f(a_1)) \neq g(f(b_0), f(b_1))
\end{aligned}
\end{equation}
%

This formula consists of two equalities $a_0 = b_0$ and $a_1 = b_1$, and a
single disequality between two terms built from $f$ and $g$. The disequality
compares two applications of $g$, whose arguments are the $f$-terms.

Congruence closure proceeds as follows. After applying the two asserted unions,
the union-find places $a_0 \equiv b_0$ and $a_1 \equiv b_1$. Then by congruence
we have that $f(a_0) \equiv f(b_0)$ and $f(a_1) \equiv f(b_1)$.

Once these equalities fire, the $g$-terms become congruent $g(f(a_0), f(a_1))
\equiv g(f(b_0), f(b_1))$. Thus, the SMT solver knows that these two terms must
be equal and thus the given formula is false.

Notice that this propagates in rounds: the initial equalities are added to the
union-find, then the two $f$-term equalities are added, and finally the
$g$-term equality is added.

\begin{definition}[Congruence Depth]
    We say that two terms are $k$-step congruent if they are congruent after $k$
    rounds of congruence closure. We say that the \emph{congruence depth} of a
    formula is the smallest $k$ such that every pair of congruent terms in the
    formula is $k$-step congruent.
\end{definition}

\begin{definition}[Congruence Width]
    For each round $r$ of congruence closure, we say that $\textit{width}(r)$ is
    the number of new equalities that are added in round $r$. We define the
    total width of a congruence closure problem to be $\max_{r \in
    0\ldots\textit{depth}} \textit{width}(r)$, i.e.\ the maximum number of new
    equalities that can be added in a single round of congruence closure.
\end{definition}

In general, if we have a large number of terms that become congruent in a single
round, we can add all of these terms to the union-find concurrently. This
motivates our parallel algorithm for congruence closure, which processes each
round of congruence closure in parallel.

\subsection{Parallel algorithms}
\label{sec:bg:parallel}

We describe our algorithm in the standard \emph{work--span} model of
shared-memory parallelism~\cite{parallel-algos}. The \emph{work} $W$ of a
computation is the total number of operations it performs; the \emph{span} (or
depth) $S$ is the length of its longest sequential dependency chain. A famous
result states that on $p$ processors with a greedy scheduler, the running time
is bounded by $O(\max(W/p, S))$, so an algorithm exposes useful parallelism when
$W/S$, its \emph{parallelism}, is large compared to the available cores.


However, congruence closure is known to be
\textsc{P}-complete~\cite{unification}:

\begin{definition}
    A problem is \textsc{P}-complete~\cite{p-complete} if
    
    \begin{enumerate}
        \item It can be solved in polynomial time, i.e. there is an algorithm
        that solves it in $O(n^k)$ time for some constant $k$ where $n$ is the
        size of the input, and
        \item Every problem in \textsc{P} can be reduced to it using a
        logarithmic-space reduction, i.e. for every problem $A$ in \textsc{P},
        there is a function $f$ that maps instances of $A$ to instances of the
        problem such that $f$ can be computed using only $O(\log n)$ space and
        such that the answer to the instance of $A$ is the same as the answer to
        the corresponding instance of the problem.
    \end{enumerate}
\end{definition}


\textsc{P}-complete problems are widely believed to not be solvable in
poly-logarithmic span and polynomial work, so they are not efficiently
parallelizable. However, this does not preclude the existence of a parallel
algorithm that works well on most practical examples. We discuss such an
algorithm in the next section.


For this paper, we assume an arbitrary-forking Multi-Process Random-Access
Machine (MP-RAM) model of parallelism~\cite{parallel-algos}. In this model, we have a
number of processors sharing an unbounded memory. Each processor performs
sequential computations and is extended with a \textsc{fork} instruction
that can spawn $k$ new threads.

In practice, we will describe our algorithm using standard parallel constructs
implemented in the \textsc{ParlayLib} library~\cite{parlaylib}, which provides a
high-level interface for parallel programming in C++. For instance, we will use 
a parallel for loop (\textbf{parfor}) to express the parallel processing of a set of
independent tasks. It is easy to see how this could have been implemented using 
\textsc{fork}, where $k$ is the number of iterations in the loop.

% We use two forms of parallel composition. \emph{Fork--join} spawns two
% subcomputations that run concurrently and synchronizes at their join point; we
% write $a \parallel b$ for the parallel composition of $a$ and $b$. A
% \textbf{parfor} is the natural extension to $n$ independent iterations, which we
% implement as a balanced fork--join tree of depth $O(\log n)$. We write
% \textbf{parfor} in pseudocode whenever the iterations are mutually independent.

Concurrent updates to shared state are mediated by atomic primitives. We rely on
\emph{compare-and-swap} (\texttt{CAS}): $\Call{CAS}{addr, old, new}$ atomically
writes $new$ to $addr$ if its current value is $old$, and returns whether it
succeeded. \texttt{CAS} is the building block for the lock-free union-find we
use in Section~\ref{subsec:uf}. When there is contention (two threads trying to 
update the same location simultaneously), it shows up as a failed \texttt{CAS}
that is retried against the new value, never as blocking.

Finally, our algorithm is structured as a sequence of \emph{bulk-synchronous}
rounds~\cite{valiant-bsp}: each round performs a large parallel computation, all
threads synchronize at a barrier, and the next round consumes the results. This
structure makes per-round work and span easy to reason about and matches how new
congruences are discovered in waves (Section~\ref{sec:bg:motivating}). The key
per-round primitive we use is \texttt{group\_by}, also called
\emph{semisort}~\cite{semisort}: given an array of (key, value) pairs it returns
the values grouped by key, in $O(n)$ work and $O(\log n)$ span on average. We
use it to gather candidate-congruent terms in each round before unioning their
classes.
