\section{Background}
\label{sec:background}


\subsection{Congruence Closure}

\emph{Congruence} ($\equiv$) requires that two terms with the same function
and pairwise-congruent children must be congruent, i.e. $f(s_1,
\ldots, s_k) \equiv f(t_1, \ldots, t_k)$ whenever $s_i \equiv t_i$ for every
$i$. \emph{Congruence closure} refers to the problem of building the smallest
equivalence relation that contains a given set of equalities and is closed under
congruence.

Typically, congruence closure is implemented using a data structure called an
\emph{e-graph}~\cite{egraphs}, which extends a union-find
data structure~\cite{unionfindtarjan} to represent equivalence classes of terms,
while maintaining congruence.


\begin{definition}[Terms]
    We define $\mathcal{T}$ to be a set of \emph{terms} over function symbols
    $F$, where
    each $t\in \mathcal{T}$ is either a \emph{leaf term}, for example $x, y, z$
    or a
    \emph{compound term} of the form $f(t_1, \ldots, t_k)$, where $f \in F$
    with $\text{arity}(f) = k$ and $t_1, \ldots, t_k \in \mathcal{T}$.
\end{definition}

For a compound term $f(x)$, we say that $x$ is a \emph{child} of $f(x)$,
and conversely that $f(x)$ is a \emph{parent} of $x$.

\begin{definition}[Congruence Closure]
    \label{def:cc}
    Given $(F, \mathcal{T}, E)$ where $F$ is a list of function symbols,
    $\mathcal{T}$ is a set of
    terms over $F$, and $E = \{a_1 = b_1, \ldots, a_n = b_n\}$ is a set of
    equalities between terms in $\mathcal{T}$ where $a_1, \ldots, a_n, b_1,
    \ldots, b_n
    \in \mathcal{T}$, the congruence closure ($\equiv$) of $(F, \mathcal{T}, E)$
    is the smallest
    equivalence closure of $=$ over $\mathcal{T}$ that respects congruence. More
    specifically:
    \begin{enumerate}
        \item $a_i \equiv b_i$ for every $i$ (input equalities $=$).
        \item $s \equiv s$ for every term $s$ (reflexivity).
        \item If $s \equiv t$ then $t \equiv s$ (symmetry).
        \item If $s \equiv t$ and $t \equiv u$ then $s \equiv u$ (transitivity).
        \item If $s_i \equiv t_i$ for every $i$ then $f(s_1, \ldots, s_k) \equiv
        f(t_1, \ldots, t_k)$ (congruence).     
    \end{enumerate}
\end{definition}

\subsection{Motivating Example}
\label{sec:bg:motivating}

To make the structure concrete, we work through a small instance of a
problem where congruence closure shines: \emph{combinational equivalence
checking} for hardware circuits~\cite{clausal-cc}. Given two circuits
$C_1$ and $C_2$ with the same inputs and outputs, one can check their 
equivalence using a construction know as a \emph{miter}: a single
circuit that feeds the shared inputs to both copies, XORs their
corresponding outputs, and ORs the results. The miter outputs $1$ on some
input iff $C_1$ and $C_2$ disagree on that input, so $C_1$ and $C_2$ are
equivalent iff the formula ``the miter outputs $1$'' is unsatisfiable.

\autoref{fig:miter} shows a simple miter, adapted from the running
example of Biere et al.~\cite{clausal-cc}, with two copies of the same
three-gate circuit. Each side $i \in \{1, 2\}$ computes
%
\begin{equation*}\label{ex:formula}
\begin{aligned}
a_i &= \mathrm{AND}(r, s), \\
x_i &= \mathrm{XOR}(u, v), \\
m_i &= \mathrm{ITE}(c,\; a_i,\; x_i),
\end{aligned}
\end{equation*}
%
where $r, s, u, v, c$ are shared inputs but the two sides use
\emph{distinct} gate instances ($a_1, a_2$ are different gate-IDs, even
though both compute $\mathrm{AND}(r,s)$, and similarly for $x_i$ and
$m_i$). The two outputs $m_1, m_2$ are combined by a top-level
$\mathrm{XOR}(m_1, m_2)$, and the miter asserts $p = m_1 \oplus m_2 = 1$.

Miters are typically encoded into conjunctive normal form (CNF) and handed
to a SAT solver, but these formulas are large and the CNF encoding
destroys the gate-level structure that makes equivalence apparent. Biere
et al.~\cite{clausal-cc} observed that miters generated from real designs
often contain many syntactically distinct gates that compute the same
function, so running congruence closure over the recovered gates can
drastically simplify (and often immediately decide) the resulting formula.

computes $a_i = \mathrm{AND}(r, s)$, $x_i = \mathrm{XOR}(u, v)$, and
$m_i = \mathrm{ITE}(c, a_i, x_i)$. The top XOR asserts $p = m_1 \oplus
m_2 = 1$; the two sub-circuits are equivalent iff this formula is
unsatisfiable.}

\end{figure}

On this miter, congruence closure proves equivalence in three rounds,
each of which discovers \emph{multiple} new congruences in parallel:

\begin{enumerate}
\item \textbf{Round 1 (leaf gates).} Both AND-gates have the same function
symbol and the same children $(r, s)$, so $a_1 \equiv a_2$ by congruence.
Likewise both XOR-gates compute over $(u, v)$, giving $x_1 \equiv x_2$.
\item \textbf{Round 2 (ITE gates).} With $a_1 \equiv a_2$ and $x_1 \equiv
x_2$ established, the two ITE-gates now have pointwise-congruent children
$(c, a_i, x_i)$, so $m_1 \equiv m_2$.
\item \textbf{Round 3 (top XOR).} The top XOR's two children are now in
the same equivalence class, so by congruence its output equals
$\mathrm{XOR}(m_1, m_1)$. If this formula is given to a SAT solver, 
can immediately determine that the output is $0$ and thus the two 
circuits are equivalent. 
\end{enumerate}

Two features of this trace are important for our work. First, the
congruences at each round are \emph{mutually independent}: $a_1 \equiv
a_2$ and $x_1 \equiv x_2$ do not depend on each other and could be
discovered concurrently, as could the merges at each subsequent level.
This is exactly the parallelism our algorithms exploit. Second, the trace
naturally separates into \emph{depth} (the number of rounds) and
\emph{width} (the number of new congruences per round). In this tiny
example both are small, but in real benchmarks the width can grow
to thousands or millions of independent merges per round. We formalize
these notions next.

\begin{definition}[Congruence Depth]
    \label{def:depth}
    We say that two terms are $k$-step congruent if they are congruent after
    $k$ rounds of congruence closure. The \emph{congruence depth} $D$ of a
    formula is the smallest $k$ such that every pair of congruent terms in
    the formula is $k$-step congruent.
\end{definition}

\begin{definition}[Congruence Width]
    For each round $r$ of congruence closure, let $\textit{width}(r)$ denote
    the number of new equalities added in round $r$. The \emph{congruence
    width} of a problem is $\max_{r \in 0 \ldots D} \textit{width}(r)$, i.e.\
    the maximum number of new equalities added in a single round.
\end{definition}

In general, if we have a large number of terms that become congruent in a single
round, we can add all of these terms to the union-find concurrently. This
motivates our parallel algorithms for congruence closure, which process each
round of congruence closure in parallel.

\subsection{Parallel Algorithms}
\label{sec:bg:parallel}

We describe our algorithms in the standard \emph{work--span} model of
shared-memory parallelism~\cite{parallel-algos}. The \emph{work} $W$ of a
computation is the total number of operations it performs; the \emph{span} (or
depth) $S$ is the length of its longest sequential dependency chain. A famous
result~\cite{brent1974,graham1969} states that on $p$ processors with a greedy
scheduler, the running time
is bounded by $O(\max(W/p, S))$, so an algorithm exposes useful parallelism when
$W/S$, its \emph{parallelism}, is large compared to the available cores.


However, congruence closure is known to be
\textsc{P}-complete~\cite{unification}, i.e. it can be solved in polynomial time (\textsc{P})
and every problem in \textsc{P} can be reduced to it using a logarithmic-space reduction.

\textsc{P}-complete problems are widely believed not to be solvable in
poly-logarithmic span and polynomial work, so they are not efficiently
parallelizable. However, this does not preclude the existence of a parallel
algorithm that works well on most practical examples. We discuss such an
algorithm in the next section.


For this paper, we assume an arbitrary-forking Multi-Process Random-Access
Machine (MP-RAM) model of parallelism~\cite{parallel-algos}. In this model, we have a
number of processors sharing an unbounded memory. Each processor performs
sequential computations and is extended with a \textsc{fork} instruction
that can spawn $k$ new threads.

In practice, we will describe our algorithms using standard parallel constructs
implemented in the \textsc{ParlayLib} library~\cite{parlaylib}, which provides a
high-level interface for parallel programming in C++. For instance, we will use 
a parallel for loop (\textbf{parfor}) to express the parallel processing of a set of
independent tasks. It is easy to see how this could have been implemented using 
\textsc{fork}, where $k$ is the number of iterations in the loop.

% We use two forms of parallel composition. \emph{Fork--join} spawns two
% subcomputations that run concurrently and synchronizes at their join point; we
% write $a \parallel b$ for the parallel composition of $a$ and $b$. A
% \textbf{parfor} is the natural extension to $n$ independent iterations, which we
% implement as a balanced fork--join tree of depth $O(\log n)$. We write
% \textbf{parfor} in pseudocode whenever the iterations are mutually independent.

Concurrent updates to shared state are mediated by atomic primitives. We rely on
\emph{compare-and-swap} (\texttt{CAS}): $\Call{\texttt{CAS}}{addr, old, new}$ atomically
writes $new$ to $addr$ if its current value is $old$, and returns whether it
succeeded. \texttt{CAS} is the building block for the lock-free union-find we
use in \autoref{subsec:uf}. Contention, where two threads attempt to update the same location
simultaneously, manifests as a failed \texttt{CAS} that is retried against
the new value, never as blocking.

Finally, our algorithms are structured as a sequence of \emph{bulk-synchronous}
rounds~\cite{valiant-bsp}: each round performs a large parallel computation, all
threads synchronize at a barrier, and the next round consumes the results. This
structure makes per-round work and span easy to reason about and matches how new
congruences are discovered in waves (\autoref{sec:bg:motivating}). The key
per-round primitive we use is \texttt{group\_by}, also called
\emph{semisort}~\cite{semisort}: given an array of (key, value) pairs it returns
the values grouped by key, in $O(n)$ work and $O(\log n)$ span on average. We
use it to gather candidate-congruent terms in each round before unioning their
classes.
